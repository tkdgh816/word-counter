# 강사용 데이터 준비 안내

교육생은 이 문서를 읽거나 스크립트를 실행할 필요가 없습니다. **현재 저장소에 공통 구현과 여러 파일 병렬 처리 실습용 데이터가 모두 포함되어 있으므로 추가 배포 없이 시작할 수 있습니다.**

## 이번에 포함한 파일

| 자료 | 제공한 입력 | 수업에서 사용할 목적 |
|---|---|---|
| KLUE YNAT 뉴스 제목 | 1,000·10,000·45,678건 CSV | 한 파일의 정확성·시간 확인 |
| 같은 뉴스의 분할본 | 서로 겹치지 않는 CSV 16개 | 여러 파일 순차 처리 기준 |
| 뉴스 8회 반복본 | 365,424건 CSV 한 개(약 27.3MB)와 분할본 16개 | 한 파일 개선 → 여러 파일 병렬 처리 |
| 뉴스 형식 변환본 | 첫 1,000건 TXT·TSV·HTML | 외부 데이터로 형식별 결과 비교 |
| Chatbot Data | 11,823건의 질문·응답 CSV | 다른 글의 성격과 여러 열 집계 |

입력 파일은 약 63.2MB입니다. 반복 데이터는 읽기·토큰 처리량을 늘리지만 단어 종류 수가 그대로이므로, 고유 단어가 많아져 `Map` 메모리가 커지는 상황을 충분히 재현하지는 못합니다. 시간 차이가 작으면 억지로 느린 코드를 만들게 하기보다 측정값과 원인을 설명하게 해도 됩니다.

## 추가로 준비한다면

### 1. KLUE MRC 지문 — 긴 글을 추가할 때 우선 추천

[원본 JSON](https://github.com/KLUE-benchmark/KLUE/tree/main/klue_benchmark/klue-mrc-v1.1)을 내려받아 지문인 `context`를 추출합니다. 여러 질문이 같은 지문을 참조하므로 **질문마다 본문을 복제하지 말고**, 본문 기준으로 중복을 제거한 뒤 CSV의 `text` 열이나 TXT로 저장하세요. 뉴스 제목보다 긴 글을 처리해보는 데 적합합니다. 원본은 [CC BY-SA 4.0](https://github.com/KLUE-benchmark/KLUE/blob/main/License.md)이며 출처·변환 기록과 라이선스를 함께 보관합니다.

크롤링은 필요 없고 **JSON → CSV/TXT 변환 스크립트**가 필요합니다. 첫 1,000개 지문, 전체 단일 파일, 같은 전체의 분할본을 준비하면 기존 실습 흐름에 연결할 수 있습니다. 고유 지문 수는 추출·중복 제거 후 기록합니다.

### 2. NSMC 영화 리뷰 — 리뷰 말투를 비교할 때

[원본 저장소](https://github.com/e9t/nsmc)의 `ratings.txt`에는 총 200,000개 리뷰가 있으며 실제 구조는 탭으로 구분된 표입니다. 파일을 `.tsv`로 구분하고 분석 열은 `document`로 지정하세요. `id`·`label`은 집계하지 않습니다.

크롤링은 필요 없습니다. 전체를 받는 것만으로도 입력으로 사용할 수 있고, 규모별·여러 파일 비교에는 **헤더를 유지하면서 레코드 단위로 추출·분할하는 스크립트**가 있으면 좋습니다. `ratings.txt`와 학습·평가 파일은 겹치므로 함께 합산하지 마세요.

원본 README의 License 항목에는 명시된 재배포 조건이 없어 **이번 저장소에는 원문을 넣지 않았습니다.** 교육용 재배포 방식과 허용 조건을 확인한 뒤 강사 배포 여부를 정하세요. 현재 공통 실습은 포함된 뉴스·대화 자료만으로 진행할 수 있습니다.

### 3. 위키문헌 작품 — 실제 HTML을 직접 수집할 때

[운수 좋은 날](https://ko.wikisource.org/wiki/운수_좋은_날) 같은 작품의 HTML을 저장하고 작품 본문을 추출합니다. 작품별 출처와 이용 조건을 함께 확인하고, 메뉴·각주·편집 안내를 어디까지 제외할지 기준을 정하세요.

한두 작품은 브라우저에서 HTML 파일로 저장할 수 있습니다. 여러 작품을 모으려면 **작품 URL 목록을 읽어 다운로드하는 스크립트**가 편합니다. 사이트의 본문 선택자는 과제 샘플의 `#content`와 다를 수 있습니다. 강사가 본문을 `#content`로 감싼 HTML로 변환해 배포하거나 사용할 선택자를 함께 안내하세요. 서로 길이가 다른 파일은 병렬 처리의 작업 분배를 관찰하기에도 좋습니다.

### 4. 한국어 위키백과 덤프 — 더 큰 심화 실험

[공식 덤프 목록](https://dumps.wikimedia.org/kowiki/latest/)에서 본문이 있는 `pages-articles-multistream.xml.bz2` 계열을 사용합니다. 압축 해제만으로 일반 TXT가 되는 자료는 아니므로 **XML과 위키 문법을 처리해 본문을 추출하는 작업**이 필요합니다. 일부 문서만 골라 TXT 또는 CSV로 만들고 출처·라이선스·추출 범위를 남깁니다.

준비 부담이 커 이번 공통 과제의 우선순위는 낮습니다. 반복 데이터보다 다양한 단어와 더 큰 파일로 확장할 때 검토할 수 있습니다.

## 포함된 입력을 다시 만들기

이미 만들어진 파일을 배포할 때는 아래 작업이 필요하지 않습니다. 재생성이 필요할 때만 **강사 환경의 Python 3**을 사용합니다. 외부 Python 패키지는 필요하지 않습니다.

1. [원본 목록](../data/manifest.json)의 `sources`에 기록된 고정 URL 네 개를 내려받습니다.
2. 한 폴더 안에 각각 `ynat-train.json`, `klue-license.txt`, `chatbot.csv`, `chatbot-license.txt` 이름으로 보관합니다. 예를 들어 프로젝트의 `data/local/sources`를 사용합니다.
3. 프로젝트 루트에서 다음을 실행합니다. Windows 환경에서는 설치에 따라 `python3` 대신 `py -3`를 사용할 수 있습니다.

```sh
python3 tools/prepare_practice_data.py --source-dir data/local/sources
```

스크립트는 원본 해시를 확인한 뒤 제공 입력과 `data/manifest.json`을 다시 씁니다. 다른 위치에서 확인하려면 `--output-dir data/local/rebuilt`를 붙입니다. 원본 구조나 버전을 바꾸려면 스크립트의 고정 URL·해시·레코드 수 검사와 데이터 설명을 함께 검토하세요. 정답 파일은 입력을 바꾸면 별도로 다시 검증해야 합니다.

한 파일과 분할 파일은 같은 레코드 집합을 사용하고, 분할 파일마다 헤더를 넣으세요. 파일 수·건수·바이트 수·분석할 열·기대 결과를 함께 제공하면 교육생이 성능 문제와 잘못된 입력 문제를 구분하기 쉽습니다.
