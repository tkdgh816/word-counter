# 필수 요구사항

[README](../README.md) · [개발 가이드](guide.md) · [심화 요구사항](advanced.md) · [진행 기록과 발표](project-guide.md)

## 과제 소개

파일이나 폴더를 입력받아 **어떤 단어가 몇 번 나오는지** 세는 Java 콘솔 프로그램을 만듭니다. TXT·CSV·TSV·HTML에서 분석할 텍스트만 골라 읽고, 자주 나온 단어를 조회하거나 결과를 파일로 저장할 수 있어야 합니다.

처음부터 아래 기능을 모두 만들 필요는 없습니다. 이 순서로 진행하세요.

| 단계 | 만들 것 | 확인 방법 |
|---|---|---|
| 1 | 작은 TXT 하나의 단어별 횟수 | `samples/equivalent/basic.txt` → 9개·6종, [정답](../expected/basic-counts.tsv)과 일치 |
| 2 | CSV·TSV·HTML에서 필요한 글만 읽기 | 같은 내용의 네 형식에서 같은 결과 |
| 3 | 조회·저장 메뉴, 잘못된 입력 안내 | 아래 실행 결과 예시대로 사용 가능 |
| 4 | 폴더의 파일을 하나씩 처리, 실패 파일 제외 | 성공한 파일만 합산 |
| 5 | 큰 파일 하나와 여러 파일의 처리 시간 기록 | 포함된 뉴스 데이터로 확인 |

객체지향 설계보다 **동작하는 기능을 먼저** 완성하세요. 익숙한 반복문과 조건문으로 시작하고, 동작을 확인한 뒤 메서드·클래스로 나눠도 됩니다.

## 실행 결과 예시

IntelliJ에서 Run을 누른 뒤 **Run 창의 콘솔에 입력**합니다. 터미널 명령을 입력하는 과제가 아닙니다. `>` 오른쪽이 사용자 입력입니다. 문구, 메뉴 번호, 화면 배치는 자유이며, 처리 시간 `12.3ms`는 설명용 숫자이므로 실제 측정값을 출력하세요. 예시에서는 반복되는 메뉴 출력을 생략했습니다.

### 파일 분석 → 조회 → 저장 → 종료

```text
문서 단어 분석기
1. 새 분석 시작
2. 상위 N개 단어 보기
3. 특정 단어 횟수 찾기
4. 전체 결과 저장
5. 최근 분석 요약 보기
0. 종료
선택 > 1
파일 또는 폴더 경로 > samples/equivalent/basic.txt

분석 완료
입력: samples/equivalent/basic.txt
파일: 시도 1개 / 성공 1개 / 실패 0개 / 지원하지 않아 건너뜀 0개
전체 단어: 9개 / 서로 다른 단어: 6개
처리 시간: 12.3ms

선택 > 2
몇 개를 볼까요? (기본 10) > 2
1. java : 3회
2. 자료구조 : 2회

선택 > 3
찾을 단어 > JAVA!
java : 3회

선택 > 4
전체 결과 6개 단어를 out/counts.tsv에 저장했습니다.

선택 > 5
입력: samples/equivalent/basic.txt
파일: 시도 1개 / 성공 1개 / 실패 0개 / 지원하지 않아 건너뜀 0개
전체 단어: 9개 / 서로 다른 단어: 6개
처리 시간: 12.3ms

선택 > 0
프로그램을 종료합니다.
```

상위 2개만 조회했더라도 저장 파일에는 **6개 단어 전체**가 들어갑니다. 저장된 `out/counts.tsv`의 내용은 다음과 같고, 열 사이는 실제 탭 문자입니다.

```tsv
word	count
java	3
자료구조	2
java17	1
ㅋㅋ	1
공부했다	1
자바를	1
```

### 잘못 입력했을 때

```text
선택 > 1
파일 또는 폴더 경로 > samples/no-such-file.txt
경로를 찾을 수 없습니다: samples/no-such-file.txt
파일 또는 폴더 경로 > samples/equivalent/basic.txt
분석 완료: 전체 9개 / 종류 6개

선택 > 2
몇 개를 볼까요? (기본 10) > abc
1 이상의 정수를 입력하세요.
몇 개를 볼까요? (기본 10) > 0
1 이상의 정수를 입력하세요.
몇 개를 볼까요? (기본 10) > 2
1. java : 3회
2. 자료구조 : 2회

선택 > 3
찾을 단어 > java 자바
```

이 짧은 예시에서는 분석 요약의 나머지 항목을 생략했습니다. 실제 프로그램은 [8. 분석 요약과 처리 시간](#8-분석-요약과-처리-시간)의 항목을 모두 출력합니다. 처리해야 하는 오류 상황의 목록은 [9. 오류와 빈 파일 처리](#9-오류와-빈-파일-처리)에 있습니다.

## 기능 요구사항

### 1. 파일 또는 폴더 선택

- 콘솔에서 경로를 입력받습니다. 상대 경로와 절대 경로를 모두 사용할 수 있어야 합니다.
- 파일이면 그 파일 하나, 폴더이면 **바로 아래의 일반 파일**을 읽습니다. 하위 폴더는 탐색하지 않으며 건너뛴 파일 수에도 포함하지 않습니다.
- 지원 확장자는 `.txt`, `.csv`, `.tsv`, `.html`, `.htm`이며 대소문자를 구분하지 않습니다.
- 지원하지 않는 파일은 건너뛰고 개수를 알려줍니다. 지원 파일이 하나도 없으면 다시 경로를 입력받습니다.
- 새 분석의 결과는 이전 결과에 더하지 않습니다. 같은 파일을 다시 분석해도 9개가 18개로 늘면 안 됩니다.
- 서로 다른 경로의 파일은 내용이 같아도 각각 셉니다. `expected`나 `out` 폴더를 입력 경로로 지정하지 마세요.

### 2. 형식별 텍스트 추출

| 입력 | 분석할 부분 | 시작할 때의 설정 |
|---|---|---|
| TXT | 파일 안의 텍스트 전체. 줄 경계는 단어 사이의 구분자 | 없음 |
| CSV | 쉼표로 구분된 표에서 지정한 열의 셀 값. 첫 레코드는 헤더 | `text` 열 |
| TSV | 탭으로 구분된 표에서 지정한 열의 셀 값. 첫 레코드는 헤더 | `document` 열 |
| HTML | 지정한 본문 요소 안의 텍스트 | CSS 선택자 `#content` |

헤더는 열 이름을 적은 첫 레코드, 레코드는 데이터 한 건, 셀은 한 레코드의 한 열에 있는 값입니다. `#content`는 `id="content"`인 요소를 뜻합니다. 헤더 자체와 분석 대상으로 지정하지 않은 열(`id`, `label`, `note` 등), HTML 태그 이름은 집계하지 않습니다. 이 과제에서 형식에 맞게 텍스트를 꺼내는 코드를 **파서**라고 부릅니다.

설정:

- CSV·TSV의 분석 열은 **하나 이상** 지정할 수 있어야 합니다. 열 이름과 HTML 선택자는 **코드의 상수로 정해도 됩니다.** 예를 들어 Chatbot 데이터는 CSV 열을 `Q`, `A`로 바꿔 실행하고, 뉴스는 다시 `text`로 바꿉니다. 설정을 바꾸는 위치를 `PROGRESS.md`에 적으세요.
- 한 번의 분석에서는 같은 형식의 파일에 같은 설정을 적용합니다. 열 구조가 다른 CSV는 설정을 바꾸어 각각 분석합니다.
- 읽기·저장은 UTF-8입니다. 제공된 입력은 BOM이 없고, 줄바꿈이 LF인지 CRLF인지는 구분하지 않고 읽습니다.

CSV·TSV 세부 규칙:

- 분석 대상 열이 여러 개라면 각 셀을 따로 단어로 분리한 뒤 횟수를 더합니다. 셀 경계에서 단어를 이어 붙이지 않습니다.
- 빈 셀이나 공백뿐인 셀은 단어를 추가하지 않습니다. 다른 분석 대상 셀은 계속 처리합니다.
- CSV의 따옴표로 감싼 값, 값 안의 쉼표, `""`로 표현한 따옴표, 값 안의 줄바꿈을 처리합니다. 셀 안에 줄바꿈이 있으면 한 레코드가 여러 줄을 차지하므로, 단순한 `split(",")`만으로는 이 요구사항을 만족할 수 없습니다.
- 제공된 TSV는 한 줄에 한 레코드이며 셀 안에 탭·줄바꿈이 없습니다. TSV에서 따옴표는 일반 문자로 취급합니다. CSV와 TSV의 따옴표 규칙이 다르다는 점에 주의하세요.
- 첫 레코드는 헤더로 읽습니다. 헤더 이름은 대소문자를 구분하며 앞뒤 공백을 제거해 비교합니다. 제공된 데이터의 헤더 이름은 비어 있지 않고 중복되지 않습니다.
- 파일이 비어 있어 헤더를 읽을 수 없거나, 지정한 분석 열이 헤더에 하나라도 없거나, 레코드의 셀 수가 헤더와 다르면 그 파일은 분석 실패입니다. 헤더만 있고 데이터 레코드가 없는 파일은 정상 처리이며 단어 0개입니다.
- Commons CSV는 `for (CSVRecord record : parser)`처럼 반복문으로 읽는 도중 만난 형식 오류(닫히지 않은 따옴표 등)를 `IOException`이 아니라 `UncheckedIOException`으로 던집니다. `catch (IOException e)`만 두면 잡히지 않고 프로그램이 멈추므로, 이 예외도 함께 잡아 그 파일을 실패로 처리하세요.

HTML 세부 규칙:

- 본문 선택자는 **정확히 한 요소**를 가리켜야 합니다. 요소를 0개 또는 2개 이상 찾으면 그 파일은 분석 실패이며 파일 이름과 원인을 안내합니다.
- 그 요소 안의 제목, 문단, 목록 등 텍스트를 읽고, 선택한 요소 밖의 문구는 제외합니다.
- 본문 요소 **안쪽에 있는** `script`, `style`, `nav`, `header`, `footer` 요소와 그 내용은 제외합니다. 기본 샘플 `basic.html`의 `#content` 안에는 머리말·꼬리말·메뉴가 들어 있어, `nav`만 제외하고 `header`·`footer`를 남기면 9개·6종이 아니라 13개·9종이 됩니다.
- HTML 주석, 태그 이름, 속성 값은 집계하지 않습니다.
- `&nbsp;`, `&#74;` 같은 HTML 문자 참조는 해석한 텍스트를 사용합니다.
- 대상은 본문이 파일 안에 들어 있는 정적 HTML입니다. JavaScript로 만들어지는 화면은 다루지 않습니다.

### 3. 단어 처리 규칙

여기서 "단어"는 아래 규칙으로 잘라낸 **토큰**, 즉 카운팅할 문자열 한 조각입니다.

1. **영문 A~Z·a~z, 숫자 0~9, 한글 가~힣·ㄱ~ㅎ·ㅏ~ㅣ**가 연속된 부분을 하나로 묶습니다.
2. 공백, 줄바꿈, 문장부호, 이모지, 한자 등 나머지 문자는 단어를 나누는 경계입니다. 이 문자를 제거하면서 양옆 단어를 이어 붙이면 안 됩니다. 구분자로 시작하는 문자열을 나눌 때 생기는 빈 문자열은 단어가 아닙니다.
3. 영문을 소문자로 바꿉니다.
4. 숫자만 있는 토큰은 제외하고, 나머지는 길이에 관계없이 셉니다.
5. 조사·어미는 그대로 둡니다. `자바`, `자바를`, `자바는`은 서로 다른 단어입니다.

| 원문 | 집계할 단어 |
|---|---|
| `Java, java!` | `java`, `java` |
| `자료구조/알고리즘` | `자료구조`, `알고리즘` |
| `java17 123` | `java17`만 집계 |
| `자바 자바를 자바는` | `자바`, `자바를`, `자바는` |
| `ㅋㅋ 😊 JAVA` | `ㅋㅋ`, `java` |
| `C++ C#` | `c`, `c` |
| `美 뉴스` | `뉴스`만 집계 |

불용어 제거, 최소 길이 필터, 형태소 분석은 이 과제에서 하지 않습니다. **기본 결과는 위 규칙 그대로** 나와야 합니다.

### 4. 단어별 횟수 집계

- 같은 토큰이 나올 때마다 1을 더합니다. `java java 자바`라면 **전체 단어 수는 3개**, **서로 다른 단어 수는 2개**입니다. 서로 다른 단어 수는 이 문서에서 '종류 수'라고 부르고, 표에서는 'N종'으로 씁니다.
- 성공한 파일이 여러 개이면 각 파일의 결과를 합칩니다.
- 데이터가 커질 수 있으니 횟수와 전체 단어 수에는 `long`을 권장합니다.
- 기본 TXT의 정답은 `java=3`, `자료구조=2`, `java17=1`, `ㅋㅋ=1`, `공부했다=1`, `자바를=1`입니다. 합계만 보지 말고 단어별 횟수도 비교하세요.

### 5. 상위 N개 단어 조회

- N은 1 이상의 정수입니다. 아무 입력 없이 Enter를 누르면 10으로 정합니다.
- 잘못된 값(`abc`, `0`, `-1`)은 안내하고 다시 입력받습니다. 단어 종류보다 큰 N이면 있는 단어까지만 보여줍니다.
- 횟수가 많은 순서로 정렬합니다. 횟수가 같으면 Java `String.compareTo`의 오름차순입니다. 별도의 한글 사전식 정렬은 필요 없습니다.
- 출력 예: `1. java : 3회`

### 6. 특정 단어 조회

- 조회 문자열에도 [3. 단어 처리 규칙](#3-단어-처리-규칙)을 적용합니다. `JAVA!`를 입력하면 `java`를 찾습니다.
- 유효한 토큰이 하나이면 그 단어의 횟수를, 없던 단어이면 `0회`를 보여줍니다.
- 토큰이 없거나(`123`, 이모지만) 둘 이상이면(`java 자바`) 단어 하나를 입력하라고 안내하고 다시 입력받습니다.
- 조회 때문에 집계 결과가 바뀌면 안 됩니다.

### 7. 전체 결과 저장

- 저장을 선택하면 **모든 단어**를 `out/counts.tsv`에 UTF-8로 저장합니다. 화면에 상위 N개만 보였더라도 전체를 저장합니다.
- 첫 줄은 `word`와 `count`, 이후는 [5. 상위 N개 단어 조회](#5-상위-n개-단어-조회)와 같은 순서의 단어·횟수이며 열 사이는 탭입니다.
- `out` 폴더가 없으면 만들고, 기존 파일은 이번 결과로 덮어씁니다.
- 성공하면 저장한 경로를 알려주고, 실패하면 이유를 알려줍니다. 저장에 실패해도 이미 구한 결과는 계속 조회할 수 있어야 합니다.
- 단어가 0개인 정상 결과는 헤더만 저장합니다.

### 8. 분석 요약과 처리 시간

분석이 끝나면 다음을 출력하고, 이후 요약 메뉴에서도 다시 볼 수 있게 합니다.

- 입력 경로
- 분석을 시도한 지원 파일 수, 성공·실패 파일 수, 지원하지 않아 건너뛴 파일 수
- 전체 단어 수와 종류 수
- 처리 시간

처리 시간은 **대상 파일 목록을 정한 뒤 첫 파일 읽기 직전부터 전체 집계 완료까지** 측정합니다. 파일 읽기, 형식 해석, 단어 분리, 집계, 결과 합산을 포함하고, 입력 대기, 최종 정렬, 결과 조회, 파일 저장은 제외합니다. `System.nanoTime()`의 시작·종료 값 차이를 구할 수 있습니다. 작은 파일도 시간을 표시하되, 특정 속도를 맞출 필요는 없습니다.

### 9. 오류와 빈 파일 처리

다음 상황에서 프로그램이 멈추거나 잘못된 합계를 내면 안 됩니다. 각 상황에서 만족해야 하는 결과는 아래와 같고, **안내 문구, 출력 형식, 처리 순서는 구현에 맡깁니다.**

| 상황 | 예시 | 만족해야 하는 결과 |
|---|---|---|
| 없는 경로·읽을 수 없는 경로 | `samples/no-such-file.txt` | 경로와 이유를 안내하고 다시 입력받음 |
| 지원하지 않는 파일을 직접 입력 | `memo.bin` | 지원 확장자를 안내하고 다시 입력받음 |
| 폴더에 지원 파일이 하나도 없음 | `.bin`만 있는 폴더 | 분석을 시작하지 않고 다시 입력받음 |
| 폴더 안에 지원하지 않는 파일이 섞임 | 폴더 안의 `memo.bin` | 건너뛰고 개수만 알림. 다른 파일은 계속 처리 |
| CSV·TSV의 필수 열 없음 | `samples/invalid/missing-column.csv` | 그 파일만 실패. 다른 파일은 계속 처리 |
| 레코드의 셀 수가 헤더와 다름 | `samples/invalid/wrong-width.tsv` | 그 파일만 실패 |
| 잘못된 CSV(닫히지 않은 따옴표 등) | `samples/invalid/broken-quote.csv` | 그 파일만 실패. **오류 전에 읽은 앞부분 단어도 합계에서 제외** |
| HTML 본문 요소를 0개 또는 2개 이상 찾음 | `samples/invalid/missing-content.html` | 그 파일만 실패 |
| 읽는 도중 그 밖의 오류 | 읽기 권한 없음, UTF-8로 읽을 수 없는 파일 | 그 파일만 실패 |
| 빈 TXT·헤더만 있는 표·빈 HTML 본문 | `samples/edge/empty.txt`, `header-only.csv`, `empty-content.html` | **정상 처리**, 단어 0개. 조회·저장 가능(헤더만 저장) |
| 저장 실패 | `out/counts.tsv`라는 이름의 폴더가 있음 | 실패 이유를 안내. 이미 구한 결과는 계속 조회 가능 |
| 잘못된 N·조회 문자열 | `abc`, `0`, `-1`, `java 자바`, `123` | 안내하고 다시 입력받음(5·6번 참고) |

실패는 파일당 한 번 세고, 실패 안내에는 파일 경로와 이유를 포함합니다. 파일별로 임시 집계를 만든 뒤 성공한 파일의 결과만 합치면 앞부분 제외 규칙을 지키기 쉽습니다.

이전 결과를 유지하거나 지우는 시점은 다음과 같습니다.

| 시점·상태 | 조회·저장·요약할 결과 |
|---|---|
| 첫 분석 전 | 먼저 분석하라고 안내. 요약 메뉴도 같은 안내 |
| 새로 입력한 경로가 잘못됨·지원 파일이 없음 | 분석을 시작하지 않음. 이전 정상 결과가 있다면 유지 |
| 지원 파일을 확인해 새 분석을 시작함 | 이전 결과 초기화 |
| 일부 파일 성공 | 성공 파일만 합산. 실패 사실도 표시 |
| 모든 파일 실패 | 실패 요약 표시. 요약 메뉴로 다시 확인할 수 있고, 단어 조회·저장은 불가 |
| 빈 파일이라도 하나 이상 정상 처리 | 단어 0개의 정상 결과로 조회·저장 가능 |

빈 파일을 분석한 뒤 모든 파일이 실패하는 새 분석을 시작했다면, 이전 빈 파일의 결과를 대신 저장하면 안 됩니다. 이 상황들을 확인하는 방법은 [검증 방법의 오류 상황 실험](#오류-상황-실험)에 있습니다.

### 10. 큰 데이터 처리

실제 데이터가 저장소에 들어 있습니다. 다운로드나 크롤링은 필요 없습니다. CSV 열을 `text`로 설정하고 아래 입력을 **각각 따로** 분석해, 입력, 파일 수, 전체 단어 수, 종류 수, 처리 시간을 `PROGRESS.md`에 적습니다.

| 순서 | 입력 | 건수 / 파일 수 | 크기 | 전체 단어 수 | 종류 수 | 정답 |
|---|---|---|---|---:|---:|---|
| 1 | `data/klue-ynat/news-1000.csv` | 1,000 / 1 | 약 71KB | 6,991 | 5,052 | [news-1000-counts.tsv](../expected/news-1000-counts.tsv) |
| 2 | `data/klue-ynat/news-10000.csv` | 10,000 / 1 | 약 729KB | 70,374 | 28,871 | [news-10000-counts.tsv](../expected/news-10000-counts.tsv) |
| 3 | `data/klue-ynat/news-full.csv` | 45,678 / 1 | 약 3.4MB | 321,084 | 78,309 | [news-full-counts.tsv](../expected/news-full-counts.tsv) |
| 4 | `data/klue-ynat/many` (16개 파일을 순서대로) | 45,678 / 16 | 합계 약 3.4MB | 321,084 | 78,309 | 3번과 같은 정답 |

- **3번과 4번은 모든 단어별 횟수가 같아야 합니다.** `many`는 전체 파일을 겹치지 않게 16개로 나눈 묶음이고, 분할 파일마다 헤더가 있습니다.
- 작은 파일은 큰 파일의 일부입니다. 네 입력을 한 번에 합산하거나 `data/klue-ynat` 폴더 전체를 지정하면 중복 집계됩니다. `many` 폴더에는 분석할 CSV만 들어 있습니다.
- KLUE YNAT의 한국어 뉴스 제목을 CSV로 변환한 데이터입니다. 레코드 수(뉴스 건수)와 전체 단어 수는 다르며, 내용이 같은 제목도 별도 레코드이면 각각 집계합니다.
- 큰 파일에서는 원문이나 단어마다 출력하지 말고 요약만 확인하세요. 파일 크기와 개수에 따라 시간이 어떻게 달라지는지 기록합니다.
- 속도 개선은 필수가 아닙니다. 끝까지 처리되는지, 결과가 맞는지, 시간을 기록했는지만 봅니다. 성능에 도전하려면 [심화 요구사항](advanced.md)을 보세요.

### 오류 상황 실험

`samples/invalid`의 파일 4개는 각각 하나씩 분석하면 모두 실패해야 합니다. 그다음 네 가지를 실험해보세요.

- **부분 성공**: `data/local/error-demo` 같은 임시 폴더에 `samples/equivalent/basic.txt`와 `samples/invalid/broken-quote.csv`를 복사해 분석하면 시도 2개, 성공 1개, 실패 1개이며 저장한 결과는 `basic-counts.tsv`와 같아야 합니다.
- **지원하지 않는 확장자**: 그 폴더에 내용은 무엇이든 상관없는 `memo.bin`을 추가하면 건너뜀 1개가 늘고, 성공·실패 수와 집계 결과는 바뀌지 않아야 합니다.
- **모든 파일 실패**: `samples/invalid` 폴더를 분석하면 시도 4개, 성공 0개, 실패 4개이며 단어 조회·저장은 안 되고 요약은 볼 수 있어야 합니다.
- **저장 실패**: `out/counts.tsv`라는 이름의 **폴더**를 만들어 저장을 시도하면 실패 안내가 나오고, 이어서 단어 조회는 계속되어야 합니다. 폴더를 지운 뒤 정상 저장도 다시 확인하세요.

### 정답 파일과 비교하는 방법

정답 TSV는 `word`와 `count`를 탭으로 구분하며 [5. 상위 N개 단어 조회](#5-상위-n개-단어-조회)의 정렬 순서로 작성되어 있습니다. 프로그램의 출력과 **단어, 횟수, 정렬 순서**를 모두 비교하며, 전체 단어 수만 같아도 단어별 횟수가 다를 수 있으니 전체 결과를 확인하세요.

탭과 줄바꿈이 보이지 않는 편집기에서는 표로 보이거나 공백처럼 보일 수 있습니다. 눈으로만 비교하지 말고, IntelliJ 왼쪽 **Project 창에서 `out/counts.tsv`와 정답 파일을 함께 선택**한 뒤 우클릭 → **Compare Files**(파일 비교)를 사용하면 탭, 공백, 순서 차이까지 정확히 확인할 수 있습니다. 큰 정답 파일도 같은 방법으로 비교합니다.
