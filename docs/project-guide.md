## 진행 기록

프로젝트 루트의 [PROGRESS.md](../PROGRESS.md)를 채우세요. Markdown은 이 문서처럼 제목, 목록, 표, 코드 블록을 쓸 수 있는 텍스트 형식이며 확장자는 `.md`입니다. 구현하지 않은 기능은 '미구현'으로 표시하고, 심화 항목은 진행한 경우에만 적습니다.

기록에 담을 내용:

- 실행 방법: JDK, 실행할 클래스, 작업 디렉터리, 설정을 바꾸는 위치와 현재 값
- 구현한 기능과 확인한 입력·결과
- 정확성 확인: 정답과 비교한 방법, 큰 데이터 네 입력의 전체 단어 수·종류 수·처리 시간
- 구현 중 해결한 문제 1~3가지: 문제, 원인, 해결 방법, 확인 결과. 잘 해결되지 않은 문제도 시도한 내용과 함께
- 심화를 진행했다면 측정 조건과 결과 표
- AI 대화나 참고 자료를 활용했다면 그 내용과 직접 확인한 방법

## 발표(10월 1일)

작성한 `PROGRESS.md`를 바탕으로 **발표용 PPT를 준비하세요.** 구현한 기능과 전체 처리 흐름, 검증 결과, 해결한 문제와 남은 문제를 정리합니다. 직접 구현·확인한 범위와 미구현 범위를 구분해서 설명하세요.

발표에서는 **프로그램의 파일 분석·조회·저장 기능을 직접 시연합니다.** 실패를 처리한 사례나 성능 실험을 했다면 그 결과도 소개하세요.

**발표 시간은 시연을 포함해 5~10분입니다.** 진행 순서는 강사 안내를 따릅니다.

발표 전에 확인하세요.

- [ ] 작은 TXT와 네 형식의 정답을 확인했다.
- [ ] 콘솔에서 분석·조회·저장을 직접 사용해봤다.
- [ ] 잘못된 입력·실패 파일·빈 파일을 구분해 처리했다.
- [ ] 새 분석을 해도 이전 횟수가 누적되지 않는다.
- [ ] 큰 파일 하나와 여러 파일의 처리 결과·시간을 기록했다.
- [ ] `PROGRESS.md`에 구현·검증·해결한 문제·남은 문제를 정리했다.
- [ ] `PROGRESS.md`를 바탕으로 발표용 PPT를 준비했다.
- [ ] IntelliJ Run으로 발표할 내용을 실행할 수 있다.
- [ ] 분석·조회·저장 시연을 포함해 5~10분 안에 발표할 수 있다.

## 제출

**10월 1일 전후로 구현한 코드와 작성한 `PROGRESS.md`를 본인의 GitHub 저장소에 업로드하고, 저장소 링크를 강사에게 전달하세요.** 전달한 저장소를 바탕으로 강사가 리뷰합니다. 비공개 저장소를 사용한다면 강사가 접근할 수 있도록 권한을 설정하세요.

`target`·`out`·개인 IDE 설정·직접 내려받은 `data/local` 파일은 `.gitignore`로 업로드에서 제외되어 있습니다. 발표에 사용할 `out/counts.tsv`는 로컬에 두고 보여주면 됩니다.

포함된 데이터의 출처·변환 내용·이용 조건은 [data/SOURCES.md](../data/SOURCES.md)에 있습니다. 직접 정한 다른 주제로 진행하는 경우에는 강사와 범위를 정합니다.

## AI 활용 범위

**웹에서 AI와 대화하며 개념 설명·구현 힌트·오류 원인·코드 검토의 도움을 받아도 됩니다.** 도움받은 내용을 이해하고 직접 코드를 작성·실행하며, 사용한 방식은 `PROGRESS.md`에 간단히 남기세요.

프로젝트 파일을 직접 작성·수정·실행하는 **코딩 에이전트는 사용하지 않습니다.** 웹 대화에서도 메서드 전체, 클래스 전체, 요구사항 전체를 완성해달라고 요청하지 마세요. 작은 의문을 해결하고 다음 코드를 스스로 작성하는 데 활용합니다. 제공된 시작 코드와 개발 가이드의 연습 예제는 사용해도 됩니다.

| 도움받아도 되는 질문 | 피할 질문 |
|---|---|
| "Map에서 처음 나온 단어인지 확인하는 방법을 설명해줘." | "단어 카운팅 메서드 전체를 완성해줘." |
| "쉼표가 들어 있는 CSV를 split으로 읽으면 왜 잘못될까?" | "CSV 파서 클래스를 전부 작성해줘." |
| "이 반복문에서 마지막 줄이 누락되는 원인을 찾을 힌트를 줘." | "이 파일을 완성된 정답 코드로 고쳐줘." |
| "이 정규식에서 +의 의미를 짧은 예로 설명해줘." | "요구사항을 붙일 테니 전체 프로젝트를 만들어줘." |
| "내가 쓴 코드에서 어떤 입력을 추가로 확인하면 좋을까?" | "메서드를 하나씩 나눠 요청할 테니 모두 구현해줘." |

API 사용법을 보여주는 몇 줄의 예시처럼 좁은 범위의 도움은 괜찮습니다. 줄 수 자체보다 **문제 해결과 구현을 누가 하고 있는지**를 기준으로 판단하세요. 질문할 때 "완성 코드는 주지 말고 원인과 다음에 확인할 부분을 설명해줘"라고 범위를 정해도 좋습니다.

도움받은 내용을 코드에 반영한 뒤에는 직접 확인합니다.

1. 코드가 어떤 입력을 받아 어떤 결과를 만드는지 설명할 수 있는가?
2. 작은 샘플의 단어별 횟수가 정답과 같은가?
3. 빈 입력이나 잘못된 입력에서도 의도한 대로 동작하는가?

대화 전문이나 별도 AI 사용 보고서는 필요하지 않습니다. 대표 질문과 배운 점, 직접 확인한 결과를 `PROGRESS.md`에 적으면 됩니다.
